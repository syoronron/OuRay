# 機能一覧（細分化）

各機能に ID を付けています。`MVP` はトヨタモビリティでの実証（最初の1〜2ルート）に必要なもの、
`後で` は実証のあとで作るものです。

---

## P0 初期設定

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P0-1 | プロジェクト作成 | Next.js 16 + Tailwind 4 + Vitest（Zicci と同じ構成） | MVP |
| P0-2 | データベース | Supabase に `supabase/migrations` を実行。全テーブル RLS 有効・ポリシーなし（サーバーからのみ操作） | MVP |
| P0-3 | 公開 | Vercel にデプロイ。トップに「システムの状態（DB接続OK）」 | MVP |
| P0-4 | デモデータ | 運送会社1社・拠点3つ・車両2台・定期ルート2本の `seed.sql` | MVP |

---

## P1 運送会社：便を作って公開する

### 1-A 拠点（出発地・到着地）

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-1 | 拠点の登録 | 名前（例：〇〇店、〇〇物流センター）、住所、緯度経度、荷受け可能な時間帯、フォークリフトの有無 | MVP |
| P1-2 | エリア | 拠点を「愛知」「東京23区」などのエリアにまとめる（荷主の検索に使う） | MVP |

### 1-B 車両

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-3 | 車両の登録 | 車名・ナンバー、車種（平ボディ／バン／ウイング／キャリアカー）、荷台の寸法、最大積載量、パレット枠数 | MVP |
| P1-4 | 設備 | パワーゲート、冷蔵・冷凍、ラッシングベルトなど（荷主の条件と照合） | 後で |
| P1-5 | ナンバーの種類 | 緑ナンバー（事業用）か白ナンバー（自家用）か。**白ナンバーの車両は有償で他社の荷物を運べないので公開できないようにする**（[確認事項](open-questions.md) Q1） | MVP |

### 1-C 定期ルートと便の自動生成

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-6 | 定期ルートの登録 | 「毎週火・金、名古屋センター 14:00 発 → 東京〇〇店 翌6:00 着」。行き便・帰り便の組で登録 | MVP |
| P1-7 | 帰り便の空き設定 | 帰り便で売るパレット枠数・最大重量（初期値＝車両の上限。自社の荷物分を差し引ける） | MVP |
| P1-8 | 便の自動生成 | 定期ルートから4週間分の便を作る。作り直しても予約が入った便は消さない（Zicci の面接枠と同じ） | MVP |
| P1-9 | 単発便の追加 | 定期ルート以外の臨時便を1件ずつ登録 | MVP |
| P1-10 | 便の公開・停止 | 下書き → 公開 → 受付終了。便ごとに「受け付けない」に切り替え | MVP |
| P1-11 | 受付の締切 | 出発の何時間前まで予約を受けるか（初期値 24時間前） | MVP |
| P1-12 | 運休 | 便を運休にすると、予約済みの荷主に運休を表示（返金・振替は運営が対応） | MVP |

### 1-D 料金

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-13 | 基本料金 | ルートごとに「1パレット枠あたり〇円」＋「重量超過 1kgあたり〇円」 | MVP |
| P1-14 | 早割・直前割 | 出発までの日数・空き具合で料金を変える（航空券と同じ） | 後で |
| P1-15 | 手数料 | 運営の手数料率（例：成約額の〇%）。運送会社の受取額を画面に表示 | MVP |

## P2 荷主：便を探して予約する

### 2-A 検索

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-1 | 便の検索 | 出発エリア・到着エリア・日付（前後3日も表示）で検索。結果は「出発日時・到着予定・空き枠・料金」 | MVP |
| P2-2 | 公開の路線ページ | 「名古屋 ⇄ 東京」など路線ごとの便カレンダー。URL・QRコードで営業先に配れる | MVP |
| P2-3 | 空き通知 | 希望の路線・日付に便が出たら知らせる（メール） | 後で |

### 2-B 荷物の入力

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-4 | 荷物の情報 | 品目（選択式）、個数、パレット枠数、総重量、寸法、荷姿（パレット／段ボール／その他） | MVP |
| P2-5 | 積めない物の確認 | 危険物・生き物・現金・貴重品・要冷蔵（非対応車両の場合）などはチェックで断る | MVP |
| P2-6 | 集荷・届け先 | MVP は **拠点まで持ち込み・拠点で受け取り**。拠点以外での集荷・配達（寄り道）は後で | MVP |
| P2-7 | 寄り道での集荷・配達 | 拠点から〇km以内なら追加料金で集荷・配達（運送会社が可否と料金を設定） | 後で |

### 2-C 予約

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-8 | 料金の見積り | 入力した荷物から料金を自動計算して表示（運賃・手数料・消費税） | MVP |
| P2-9 | 予約の確定方式 | 便ごとに「即時確定」か「運送会社が承認してから確定」かを選べる。**実証では承認制** | MVP |
| P2-10 | 予約の取りすぎ防止 | 便を1行ロックしてから残り枠・残り重量を確認して登録（1つの処理の中で行う） | MVP |
| P2-11 | 予約確認ページ | 推測できないURL（`/b/専用の値`）。予約内容・状態・集荷/受取の場所と時間・キャンセル | MVP |
| P2-12 | キャンセル | 出発〇時間前までは荷主が自分で取り消し（枠はすぐ空く）。以降は運営に連絡 | MVP |
| P2-13 | 運送の約款への同意 | 予約時に約款・責任の範囲・補償の上限に同意（[確認事項](open-questions.md) Q4） | MVP |

## P3 運行当日

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P3-1 | 当日の積込リスト | 運送会社の画面に、その便で積む荷物・荷主・個数・置き場所を一覧（印刷可） | MVP |
| P3-2 | 状態を進める | ①予約確定 → ②集荷・積込済み → ③輸送中 → ④到着・受け渡し済み。ボタンで進める | MVP |
| P3-3 | 写真の記録 | 積込時・受け渡し時の荷物の写真（破損トラブルの証拠） | MVP |
| P3-4 | 受け取りのサイン | 受取人の名前（とサイン）を記録 | 後で |
| P3-5 | 遅れ・事故の報告 | 到着の遅れ、破損・紛失を運送会社が報告 → 荷主ページと運営に表示 | MVP |
| P3-6 | 位置情報 | ドライバーのスマホで現在地を共有 | 後で |

荷主の予約確認ページ（P2-11）に、①〜④の進み具合をそのまま表示します（Zicci の「応募状況のページ」と同じ考え方）。

## P4 お金と書類

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P4-1 | 料金の確定 | 実際の重量・枠数で料金を確定（差があれば運送会社が修正） | MVP |
| P4-2 | 運送の書面 | 運送の条件（運賃・料金・付帯作業）を書面（PDF）で残す（[確認事項](open-questions.md) Q3） | MVP |
| P4-3 | 請求書 | 月ごとに荷主へ請求書（インボイス制度の登録番号つき）。実証では銀行振込 | MVP |
| P4-4 | 支払い明細 | 運送会社への支払い（運賃 − 手数料）の月次明細 | MVP |
| P4-5 | カード決済 | 予約時にカード払い（Stripe など） | 後で |

## P5 アカウントと審査

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P5-1 | ログイン | 運送会社・荷主・運営で別々の画面。実証の最初は Zicci と同じ「管理画面パスワード」で代用 | MVP |
| P5-2 | 会社ごとのデータ分離 | 運送会社は自社の便・予約だけ、荷主は自社の予約だけ見える | 後で（P5本番） |
| P5-3 | 荷主の登録・審査 | 会社名・法人番号・担当者・連絡先。運営が確認してから予約できる | MVP（運営が手で承認） |
| P5-4 | 運送会社の審査 | 一般貨物自動車運送事業の許可番号、貨物保険の加入を確認 | MVP（運営が手で承認） |
| P5-5 | 評価 | 荷主・運送会社がお互いを評価（時間どおり・荷物の状態） | 後で |

## P6 AI（任意）

|---|---|---|---|
| P6-1 | 配車表の読み取り | 配車表（Excel・紙の写真）から便を作る（Zicci のシフト表読み取りと同じ流れ） | 後で |

## 運営の画面

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| A-1 | ダッシュボード | 今週の便数・空き枠・予約枠・積載率（帰り便がどれだけ埋まったか） | MVP |
| A-2 | 審査 | 荷主・運送会社の承認待ち一覧 | MVP |
| A-3 | トラブル対応 | 遅れ・事故の報告一覧、運休の影響を受けた予約 | MVP |

## 作る順番（MVP の最短ルート）

1. P0 → P1-1〜3, 5, 6〜8, 10〜11, 13 （運送会社が便を出せる）
2. P2-1, 4〜5, 8〜11 （荷主が予約できる。承認制）
3. P3-1〜3 （当日の運用が回る）
4. P2-12〜13, P1-12, P3-5 （キャンセル・運休・トラブル）
5. P4-1〜4, A-1〜3 （お金と運営）
6. P5（本番のログイン）→ 後でのもの
