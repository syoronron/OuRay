# 機能一覧（細分化）

各機能に ID を付けています。`MVP` はトヨタモビリティでの実証（最初の1〜2ルート）に必要なもの、
`後で` は実証のあとで作るものです。

---

## P0 初期設定

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P0-1 | プロジェクト作成 | Next.js 16 + Tailwind 4 + Vitest（Zicci と同じ構成） | MVP |
| P0-2 | データベース | Supabase に `supabase/migrations` を実行。全テーブル RLS 有効・ポリシーなし（サーバーからのみ操作） | MVP |
| P0-3 | 公開 | Vercel にデプロイ。トップに「システムの状態（DB接続OK）」 | MVP |
| P0-4 | デモデータ | 運送会社1社・拠点3つ・車両2台・定期ルート2本の `seed.sql` | MVP |

## P1 運送会社：便を作って公開する（✅ 作成済み。P1-4 設備の一部・P1-14 早割は後で）

### 1-A 拠点（出発地・到着地）

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-1 | 拠点の登録 | 名前（例：〇〇店、〇〇物流センター）、住所、緯度経度、荷受け可能な時間帯、フォークリフトの有無 | MVP |
| P1-2 | エリア | 拠点を「愛知」「東京23区」などのエリアにまとめる（荷主の検索に使う） | MVP |

### 1-B 車両

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-3 | 車両の登録 | 車名・ナンバー、車種（平ボディ／バン／ウイング／キャリアカー）、荷台の寸法、最大積載量、パレット枠数 | MVP |
| P1-4 | 設備 | パワーゲート、冷蔵・冷凍、ラッシングベルトなど（荷主の条件と照合） | 後で |
| P1-5 | ナンバーの種類 | 緑ナンバー（事業用）か白ナンバー（自家用）か。トヨタモビリティは緑ナンバーの見込み。**白ナンバーの車両は有償で他社の荷物を運べないので公開できないようにする**（P7 で他社が入ってきたときの安全装置） | MVP |

### 1-C 定期ルートと便の自動生成

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-6 | 定期ルートの登録 | 「毎週火・金、名古屋センター 14:00 発 → 東京〇〇店 翌6:00 着」。行き便・帰り便の組で登録 | MVP |
| P1-7 | 空きの設定 | 便で売るパレット枠数・最大重量（初期値＝車両の上限）。帰り便は全部を売るのが基本。行き便も同業とのシェアで埋まらなかった日は、残りを売れる | MVP |
| P1-7b | 便ごとの空きの修正 | 「今週の帰りは自社の返却品が2枠ある」など、その便だけ売る枠を減らす | MVP |
| P1-8 | 便の自動生成 | 定期ルートから4週間分の便を作る。作り直しても予約が入った便は消さない（Zicci の面接枠と同じ） | MVP |
| P1-9 | 単発便の追加 | 定期ルート以外の臨時便を1件ずつ登録 | MVP |
| P1-10 | 便の公開・停止 | 下書き → 公開 → 受付終了。便ごとに「受け付けない」に切り替え | MVP |
| P1-11 | 受付の締切 | 出発の何時間前まで予約を受けるか（初期値 24時間前） | MVP |
| P1-12 | 運休 | 便を運休にすると、予約済みの荷主に運休を表示（返金・振替は運営が対応） | MVP |

### 1-D 料金

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P1-13 | 基本料金 | **運賃は運送会社が決める**（仲介のため OuRay は決めない）。ルートごとに「1パレット枠あたり〇円」 | MVP |
| P1-14 | 早割・直前割 | 出発までの日数・空き具合で料金を変える（航空券と同じ）。ルールは運送会社が選ぶ | 後で |
| P1-16 | 受け入れる品目 | ルート・便ごとに受け入れる品目を選ぶ（例：衛生物は受けない／受ける）。衛生物を受ける場合は、積み方・清掃の決まりに同意（下の「衛生物の扱い」） | MVP |
| P1-17 | 寄り道の設定 | 拠点から〇km以内なら、施設などでの集荷・配達を受ける。1か所あたりの料金 | MVP（介護のニーズで前倒し） |
| P1-15 | 手数料 | OuRay の手数料率（例：成約額の〇%）。運送会社の画面に「運賃・手数料・受取額」を表示 | MVP |

## P2 荷主：便を探して予約する

### 2-A 検索

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-1 | 便の検索 | 出発エリア・到着エリア・日付（前後3日も表示）で検索。結果は「出発日時・到着予定・空き枠・料金」 | MVP |
| P2-2 | 公開の路線ページ | 「名古屋 ⇄ 東京」など路線ごとの便カレンダー。URL・QRコードで営業先に配れる | MVP |
| P2-3 | 空き通知 | 希望の路線・日付に便が出たら知らせる（メール） | 後で |

### 2-B 荷物の入力

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-4 | 荷物の情報 | 品目（選択式）、個数、パレット枠数、総重量、寸法、荷姿（パレット／段ボール／カゴ台車／その他） | MVP |
| P2-5 | 積めない物の確認 | 危険物・生き物・現金・貴重品・要冷蔵（非対応車両の場合）・**廃棄物（使用済み紙おむつ等）** はチェックで断る | MVP |
| P2-6 | 集荷・届け先 | 拠点まで持ち込み・拠点で受け取りが基本 | MVP |
| P2-7 | 寄り道での集荷・配達 | 便が寄り道を受けていれば、施設の住所を入れて集荷・配達を頼める（料金は P1-17）。介護施設は拠点まで持ち込めないことが多いので **MVP に前倒し** | MVP |

### 2-C 予約

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P2-8 | 料金の見積り | 入力した荷物から料金を自動計算して表示（運賃・手数料・消費税） | MVP |
| P2-9 | 予約の確定方式 | 便ごとに「即時確定」か「運送会社が承認してから確定」かを選べる。**実証では承認制** | MVP |
| P2-10 | 予約の取りすぎ防止 | 便を1行ロックしてから残り枠・残り重量を確認して登録（1つの処理の中で行う） | MVP |
| P2-11 | 予約確認ページ | 推測できないURL（`/b/専用の値`）。予約内容・状態・集荷/受取の場所と時間・キャンセル | MVP |
| P2-12 | キャンセル | 出発〇時間前までは荷主が自分で取り消し（枠はすぐ空く）。以降は運営に連絡 | MVP |
| P2-14 | 定期予約 | 「毎週火曜の帰り便に2枠」を1回の申込で予約。便が作られるたびに予約（申込中）を自動で作る。空きが足りない回は荷主と運送会社に知らせる | MVP（介護のニーズ） |
| P2-15 | 定期予約の休み・変更 | 「今週はなし」「今週は3枠」を荷主が便ごとに変更 | MVP |
| P2-13 | 契約の相手の表示と同意 | 予約時に「運送の契約相手は〇〇運送（許可番号）、OuRay は仲介」と明示し、その運送会社の約款・補償の上限と、OuRay の利用規約に同意（[確認事項](open-questions.md) Q4） | MVP |

## P3 運行当日

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P3-1 | 当日の積込リスト | 運送会社の画面に、その便で積む荷物・荷主・個数・置き場所を一覧（印刷可） | MVP |
| P3-2 | 状態を進める | ①予約確定 → ②集荷・積込済み → ③輸送中 → ④到着・受け渡し済み。ボタンで進める | MVP |
| P3-3 | 写真の記録 | 積込時・受け渡し時の荷物の写真（破損トラブルの証拠） | MVP |
| P3-4 | 受け取りのサイン | 受取人の名前（とサイン）を記録 | 後で |
| P3-5 | 遅れ・事故の報告 | 到着の遅れ、破損・紛失を運送会社が報告 → 荷主ページと運営に表示 | MVP |
| P3-6 | 位置情報 | ドライバーのスマホで現在地を共有 | 後で |

荷主の予約確認ページ（P2-11）に、①〜④の進み具合をそのまま表示します（Zicci の「応募状況のページ」と同じ考え方）。

## P4 お金と書類

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
仲介なので、お金の流れは2本に分けます。

```
荷主 ──（運賃の請求・支払い）── 運送会社 ──（手数料の請求・支払い）── OuRay
```

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P4-1 | 料金の確定 | 実際の重量・枠数で料金を確定（差があれば運送会社が修正し、荷主に表示） | MVP |
| P4-2 | 運送の書面 | 予約が確定したら、運送会社名義の書面（運賃・料金・付帯作業・荷主・区間）を PDF で自動作成し、双方のページに置く（[確認事項](open-questions.md) Q3） | MVP |
| P4-3 | 運賃の請求書 | **運送会社名義** で荷主への月次請求書を OuRay が作成（運送会社のインボイス登録番号つき）。支払いは荷主→運送会社の銀行振込 | MVP |
| P4-4 | 手数料の請求書 | **OuRay 名義** で運送会社への月次の手数料請求書（OuRay のインボイス登録番号つき） | MVP |
| P4-5 | カード決済・収納代行 | 予約時にカード払いし、OuRay がまとめて受け取って運送会社に渡す（Stripe Connect など） | 後で |

## 衛生物の扱い（介護施設のリネンなど）

使用済みのシーツ・タオルは「洗うために運ぶ物」で、廃棄物ではありません。
ただし、においや感染症への配慮が必要なので、運送会社・荷主の双方に決まりを守ってもらいます。

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| H-1 | 衛生物の表示 | 品目に「衛生物」の印。検索結果で「衛生物OKの便」だけに絞れる | MVP |
| H-2 | 荷主の約束 | 密閉した袋・ふた付きの容器に入れる、外側を汚さない、感染症の疑いがある物は別扱い（または不可）を予約時に確認 | MVP |
| H-3 | 運送会社の約束 | 他の荷物と分けて積む、受け渡し後の荷台の清掃、次の便（行きの部品）に影響しない運用を確認 | MVP |
| H-4 | 清掃の記録 | 衛生物を運んだ便のあと、清掃したことを記録（写真つき） | MVP |
| H-5 | 洗濯済みとの往復 | クリーニング工場 → 施設（洗濯済み）も同じルートの逆向きで運べるか。ただし **同じ便で使用済みと洗濯済みを混ぜない** | 後で |

## P7 他の運送会社に開放（物流の空きが集まる場所へ）

トヨタモビリティで回ることを確かめてから、他の運送会社も空きを出せるようにします。

| ID | 機能 | 内容 | 区分 |
|---|---|---|---|
| P7-1 | 運送会社の自己登録 | 会社情報・許可番号・保険証券・インボイス番号を入力して申請 → 運営が審査（P5-4） | 後で |
| P7-2 | 運送会社のプロフィール | 会社名・許可番号・対応エリア・車種・実績（運んだ件数・時間どおり率）を荷主に公開 | 後で |
| P7-3 | 複数社の便をまとめて検索 | 同じ路線・日付の便を会社をまたいで並べる（料金順・到着の早い順） | 後で |
| P7-4 | 評価 | 荷主・運送会社がお互いを評価（時間どおり・荷物の状態・連絡） | 後で |
| P7-5 | 手数料の設定 | 会社ごとの手数料率（初期参加の割引など） | 後で |
| P7-6 | 連携 | 運送会社の配車システム・動態管理（位置情報）から便・状態を自動で取り込む API | 後で |
| P7-6b | 許可を持つ運送会社の品目 | 廃棄物の収集運搬業の許可を持つ運送会社だけが、使用済み紙おむつなどを受けられるようにする（許可番号と許可の地域を審査） | 将来 |
| P7-7 | 乗り継ぎ | 2つの便を拠点で乗り継いで、直通便のない区間を運ぶ（航空便の乗り継ぎと同じ） | 将来 |

MVP の段階から、データはすべて会社ごとに持ち、画面も「どの運送会社の便か」を表示しておきます（P7 で作り直さないため）。

|---|---|---|---|

## 作る順番（MVP の最短ルート）

1. P0 → P1-1〜3, 5, 6〜8, 10〜11, 13 （運送会社が便を出せる）
2. P2-1, 4〜5, 8〜11, P1-16〜17, P2-7 （荷主が予約できる。承認制。品目と寄り道）
2b. P2-14〜15, H-1〜4 （定期予約と衛生物：介護施設のリネンで実証できる形に）
3. P3-1〜3 （当日の運用が回る）
4. P2-12〜13, P1-12, P3-5 （キャンセル・運休・トラブル）
5. P4-1〜4, A-1〜3 （お金と運営）
6. P5（本番のログイン）→ P7（他の運送会社に開放）→ 後でのもの
