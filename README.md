# OuRay

トラックの**帰り便の空いた荷台**を、飛行機の座席のように「便（日時・出発地・到着地・空きスペース）」として公開し、
安く荷物を運びたい事業者が予約できる、物流シェアリングのWebアプリです。

最初の利用先はトヨタモビリティを想定しています。

- トラックは緑ナンバー（事業用）の見込み → 他社の荷物を運賃をもらって運べる
- 行きは同業とシェアリングして自動車部品で満載、**帰りは空荷**
- 将来は **トヨタモビリティ以外の運送会社も空きを出せる** ようにして、空きのあるトラックが集まる場所にする

> いまは **P2** まで。運送会社が便を公開し、荷主が便を探して予約を申し込み、運送会社が承認できます。
> 次は P2 の続き（定期予約）と P3（運行当日の記録）です。

## どんな荷物に向いているか

OuRay の便は **日時と場所が決まっていて、速くはないが、安い**（航空便でいえば LCC、または船便）。
次の3つがそろう荷物に向いています。

| 向いている | 理由 |
|---|---|
| **定期的に出る** | 毎週同じ曜日に走る便と合わせやすい。定期予約で毎回の手間がない |
| **急がない** | 翌日〜数日以内に届けばよい |
| **費用を下げたい** | 帰り便の空きなので、専用便を頼むより安くできる |

ヒアリングで見えてきた荷物の例：

- **介護施設の使用済みシーツ・タオル**（クリーニング工場へ）… 毎週決まって出る・急がない・費用を抑えたい（1社目のヒアリング）
- **自動車部品の通い箱の返却** … 行きの部品の流れの逆方向

> ⚠️ **使用済みの紙おむつは廃棄物** の扱いになり、運ぶには廃棄物の収集運搬業の許可が必要です。
> OuRay では当面受け付けません（[確認事項](docs/open-questions.md) Q8）。未使用の紙おむつ（介護用品の配送）は運べます。

## OuRay の立ち位置：仲介プラットフォーム

```
 荷主 ──── 運送契約（運賃・責任） ──── 運送会社
   \                                    /
    \── 予約・連絡・書面の作成 ── OuRay ──/   ← 場を提供し、手数料を受け取る
```

- **運送の契約は荷主と運送会社の間で結ぶ**。OuRay は契約の当事者にならず、運送も引き受けない
- 運賃は運送会社が決める。OuRay は便の公開・検索・予約・連絡・書面づくりの「場」を提供する
- OuRay の収入は、成約した予約に対する手数料（運送会社から受け取る想定）

## 登場する人

| 呼び方 | 誰か | このアプリでやること |
|---|---|---|
| **運送会社**（キャリア） | 最初はトヨタモビリティ。将来は他の運送会社も | 車両・定期ルートを登録し、空きを「便」として公開。予約を承認して運ぶ |
| **荷主** | 安く荷物を運びたい事業者（自動車部品の同業、介護施設・リネン業者など） | 便を検索して予約（定期予約も）。荷物の進み具合を確認 |
| **運営** | OuRay の運営者 | 事業者の審査、トラブル時の取り次ぎ、手数料の精算 |

## 基本の考え方（航空便モデル）

```
定期ルート（毎週火・金 名古屋→東京、帰り 東京→名古屋）
   ※ 主役は帰り便。行き便に空きが出た日も同じ仕組みで公開できる
   └─ 自動で「便」を作る（Zicci のシフト → 面接枠 の自動生成と同じ考え方）
        └─ 便ごとに「空きスペース」＝ パレット枠 × 最大重量 を公開
             └─ 荷主が「日付・出発地・到着地」で検索 → パレット枠を予約
```

- 荷台を **パレット枠（1枠＝1.1m×1.1m の1パレット分）** で区切って売る。飛行機の座席と同じで、在庫として数えられる
- 重量の上限も同時に見る（枠が空いていても重すぎれば予約できない）
- 予約の取りすぎは **データベースの処理の中で** 防ぐ（Zicci の重複予約防止と同じ方式）

## セットアップ手順

### 1. Supabase（データベース）を用意する

1. https://supabase.com で無料アカウントを作り、「New project」でプロジェクトを作成します
   - Region は **Northeast Asia (Tokyo)** を選びます
   - Database Password は控えておきます（今回のアプリでは使いませんが、管理用に必要です）
2. 左メニューの **SQL Editor** を開き、次のファイルを順番に貼り付けて「Run」を押します
   1. `supabase/migrations/20261201000000_init.sql`（テーブル作成・予約の受付処理）
   2. `supabase/migrations/20261202000000_trips.sql`（便の作成・公開・運休の処理）
   3. `supabase/migrations/20261203000000_grants.sql`（アプリにテーブルの読み書きを許可する）
   4. `supabase/migrations/20261204000000_trip_codes.sql`（便名：DM102 など）
   5. `supabase/migrations/20261205000000_bookings.sql`（予約の申込・承認・キャンセル）
   6. `supabase/seed.sql`（デモ用データ）

   > どれも何回実行しても大丈夫です。
> トップページに「permission denied for table ...」と出たら、3 を実行していないか、実行前に作ったテーブルがあります。3 をもう一度実行してください。
> 「column ... number does not exist」などと出たら、4 を実行してください。
3. **Project Settings** から次の2つを控えます
   - **Data API → Project URL** … `SUPABASE_URL`
   - **API Keys → Secret key**（`sb_secret_` で始まるもの）… `SUPABASE_SECRET_KEY`
     （画面が古い場合は `service_role` キーでも動きます）

> ⚠️ Secret key は「何でもできる鍵」です。GitHub やチャットに貼らないでください。

### 2. 手元で動かす（任意）

```bash
cp .env.example .env.local   # 作成した .env.local に上の2つの値を書く
npm install
npm run dev                  # http://localhost:3000 を開く
```

トップページ下部の「SYSTEM」が **データベース接続OK** になれば成功です。

```bash
npm test                     # 金額の計算のテスト
```

### 3. Vercel で公開する

1. https://vercel.com で GitHub アカウントを使って無料登録します
2. 「Add New… → Project」で `OuRay` リポジトリを選んで Import します
3. **Environment Variables** に次の3つを追加します
   - `SUPABASE_URL` / `SUPABASE_SECRET_KEY`（Supabase の値）
   - `ADMIN_PASSWORD`（運送会社の管理画面のパスワード。4文字以上。自分で決める）
4. 「Deploy」を押すと公開URLが発行されます。トップページの「SYSTEM」が **データベース接続OK** になれば P0 完了です

## 運送会社の管理画面（P1）

トップページの「空きを出す」→ パスワードでログイン（`/carrier`）。下のタブは左から：

| タブ | 内容 |
|---|---|
| 便（`/carrier`） | 週ごとの便の一覧。「定期ルートから便を作る」で今日から4週間分を下書きで作り、「この週の下書きを公開する」で荷主の検索に出す |
| 定期ルート | 毎週走るルート（行き・帰り、曜日、時刻、車両、売る空き、料金、締切、受け入れる品目、寄り道） |
| 拠点・車両 | 荷物の受け渡し場所（エリア・荷受け時間・フォークリフト）と車両（ナンバーの種類・パレット枠数・最大積載量） |

- **便の作り方**：定期ルートの曜日・時刻から便を作ります。作り直しても、公開中の便・予約のある便は消えません（下書きだけ作り直します）
- **便ごとの調整**：便を開いて、その便だけ売る枠・重量・料金・品目を変えられます（例：今週の帰りは自社の荷物が2枠ある）。予約済みの量より少なく・車両の上限より多くはできません
- **状態**：下書き → 公開中 →（受付終了 ⇄ 受付再開）。走らない日は「運休」（予約があれば荷主のページに表示。元に戻せません）
- **公開できない便**：売る枠が 0（満載の行き便など）、締切を過ぎた便、白ナンバーの車両の便
- **品目**：便ごとに受け入れる品目を選びます。衛生物（使用済みリネン）は選んだ便だけ。廃棄物（使用済み紙おむつ）は選べません
- 臨時の便は「便」タブの「臨時の便を1件だけ追加する」から
- ログイン中は、デモの運送会社（`seed.sql`）のデータだけを扱います。会社ごとのログインは P5 で作ります

## 便をさがす（荷主向けの公開ページ）

トップページの「便をさがす」（`/trips`）。空港の「出発フライト一覧」と同じ並び・見た目にしています。

- 上から：**出発便／到着便** の切り替え → 検索（拠点・エリア・運送会社・便名）→ **日付・時間帯・エリア** → **絞り込み**（空きのある便だけ・衛生物OK・寄り道できる）→ **↑ 前の便** → 便の一覧 → 最終更新
- 1便ごとの行：上の段に **定刻・行き先・便名（DM102）・運送会社**、下の段に **出発の拠点と到着時刻・空き・1枠の料金・衛生物OK・寄り道**、右に **状況の札**
  - 状況：受付中／残りN枠（2枠以下）／満載／受付終了（締切後・受付終了）／運休
- 今日は「現在時刻」以降の便を表示し、それより前は「前の便（N件）」にまとめます
- 便の詳細（`/trips/便のID`）：出発・到着の時刻と拠点、運送会社と許可番号、空きと料金、運べる荷物、持ち込む場所・受け取る場所。予約は P2 で作ります
- 下書きの便・審査の済んでいない運送会社の便は出しません。車両のナンバー・他の荷主の予約内容も出しません
- **便名** ＝ 運送会社の略号 ＋ 定期ルートの番号（定期ルートの画面で番号を設定）。臨時の便は「臨時」

## 予約（P2）

**荷主**（ログインなし）

1. 「便をさがす」→ 便を選ぶ →「この便を予約する」（`/trips/便のID/book`）
2. ①ご依頼主（会社名・担当者・電話）②荷物（品目・荷姿・個数・パレット枠・重さ）③持ち込み・受け取り（拠点 or 施設などで集荷・配達）④料金と同意
   - 料金（運賃・寄り道・消費税・合計）は入力に合わせてその場で表示
   - 積めない物（危険物・廃棄物など）が入っていないことの確認、衛生物は「密閉した袋・容器に入れる」確認が必要
   - 「運送の契約は荷主と運送会社の間。OuRay は仲介」に同意して申し込む
3. 申し込むと **予約確認ページ**（`/b/推測できない値`）が開く。URL を保存してもらう（メールなどのお知らせはしない）
   - 進み具合：申込 → 予約確定 → 積込 → 輸送中 → 受け渡し。お断り・運休のときは理由を表示
   - 予約の締切までは、自分でキャンセルできる（枠はすぐ空く）
- 初めての荷主は「審査待ち」として登録され、予約は必ず運送会社の承認が必要（会社名と電話番号が同じなら同じ荷主として扱う）
- 同じ接続元からの申込は1時間に10回まで

**運送会社**

- 「便」タブに「承認待ちの予約が N件」と表示 →「予約」タブ（`/carrier/bookings`）
- 申込ごとに荷主（初めての荷主には印）・荷物・集荷/配達の住所・連絡先・金額（運賃・手数料・受取額）を確認し、**承認** か **お断り（理由を入力）**
- 便の詳細にも、その便の予約の一覧を表示

**お金**：運賃は運送会社が荷主に請求（税込）。OuRay の手数料（運賃の10%、`src/lib/booking.ts`）は運送会社に請求。予約時の単価・手数料率は予約に保存する

## セキュリティの方針

- 運送会社の管理画面（`/carrier`）は、環境変数 `ADMIN_PASSWORD` のパスワードでログインした人だけが使えます（Zicci と同じ仕組み）
  - 未設定（または4文字未満）のときは誰もログインできません。5回続けて間違えると10分間ログインできなくなります
  - 実際の取引の情報を扱う前に、推測されにくい長めのパスワードにしてください
- 便の状態の変更・空きの変更は、データベースの関数の中で便をロックしてから確認します（予約の取りすぎと、予約済みより少ない空きを防ぐ）
- どの操作も、会社（`company_id`）で絞ってから行います。他社の便・ルート・予約は変更できません
- 荷主の予約確認ページは、推測できない64文字の値でだけ開けます。検索エンジンには載せません
- 荷主の公開ページには、他の荷主の情報・車両のナンバーは出しません（運送会社の画面には、自社の便の予約の荷主だけを出します）

- すべてのテーブルで RLS（行レベルセキュリティ）を有効にしています。ポリシーを作っていないため、ブラウザから直接データベースを読み書きすることはできません
- データベースの操作は、すべてサーバー側（Secret key を持つ Next.js のサーバー処理）で行います
- 予約の取りすぎは、データベースの関数 `create_booking()` の中で便をロックしてから確認して防ぎます
- 廃棄物（使用済み紙おむつなど）の予約は、データベースの段階で必ず断ります
